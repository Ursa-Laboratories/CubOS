# 04 — Serial driver hardening (GRBL framing, stop/feed-hold, reconnect state)

Read `progress/2026-07-07-audit/00-INDEX.md` "Ground rules" first. Repo `/Users/alexchan/Documents/Ursa/CubOS`, `venv/bin/python`, offline only (mock serial in tests — never open a port), no commits, regression test per fix.

Scope: `src/gantry/gantry_driver/driver.py`, `src/gantry/gantry.py`, `src/gantry/session.py`, `src/gantry/offline.py`, their tests. This is the safety-critical layer — every fix below is invisible to the current suite because tests mock `_read_serial` with idealized complete strings.

## Fixes

1. **HIGH — `stop()` (feed hold) always raises after a 5s stall and leaves GRBL in Hold.** `driver.py:406-408`: `stop()` routes `"!"` through `execute_command`, which runs `_wait_until_idle` (`:525-546`) — but feed hold parks GRBL in `Hold`, which never becomes `Idle` (only `~` cycle-start or reset exits Hold; nothing in the repo sends `~`). `GantrySession.feed_hold()` (`session.py:257-260`) propagates the raise. Fix: make `stop()` a raw realtime write (`self.ser_mill.write(b"!")` — no line protocol, no idle wait), verify via one `?` that state is Hold, and add explicit `resume()` (`~`) and a documented reset path. Update `tests/gantry/driver/test_gantry_driver.py:253-262`, which currently enshrines the Hold→timeout bug as expected behavior.
2. **HIGH — `feed_hold_interrupt` reads serial concurrently with the locked operation thread.** `session.py:262-273` bypasses the operation lock (correct) but calls `gantry.stop()`, which READS the port — two unsynchronized readers steal each other's bytes and desync the stream. `jog_cancel_interrupt` (`:280-282`) is safe because `Mill.jog_cancel` is write-only. Fix: expose a write-only `Mill.feed_hold_realtime()` and use it from the interrupt path (composes with fix 1).
3. **HIGH — `_read_serial` has no line framing.** `driver.py:574-580` (`read(1)` + `read_all()`): a status split across USB packets can truncate `WPos:...,35.000` to `...,3` and `wpos_pattern` (`:43`) parses Z=3.0 as valid — `_is_already_at_target` (`:826-833`) can skip a commanded move, session jog bounds checks (`session.py:797-806`) validate against a wrong position, and the bad value is cached in `_last_position`. Fix: frame reads line-by-line (`readline()` loop; a status report is complete only with its closing `>`), discard incomplete fragments, and strip lines in `_read_serial` (which also fixes `current_status()`'s dead `while status in ["", "ok"]` comparison at `:553` — `"ok\r\n"` never matches).
4. **HIGH — a failed `finalize_calibration_origin` silently drops the soft-limit restore obligation.** `session.py:525-528`: the `except` clears `_calibration_restore_soft_limits`, so both `restore_calibration_soft_limits()` (`:449-453`) and the disconnect-time restore (`:867-871`) become no-ops and the machine keeps running with `$20=0`. Fix: on failure, eagerly attempt `set_soft_limits_enabled(True)` and keep the flag set until a confirmed `$20=1`.
5. **MEDIUM — GRBL casing bugs.** `_wait_until_idle` (`driver.py:529-545`) matches lowercase `"error"`/`"alarm"` but after the first iteration polls raw text (`<Alarm|...>` never classified — surfaces as a 5s timeout); `Gantry.is_healthy()` (`gantry.py:131`) checks `"Alarm"`/`"Error"` case-sensitively while GRBL pushes `ALARM:N`/`error:N`, so a buffered alarm passes the pre-run health gate (`session.py:582,605`). Fix: compare case-insensitively in both.
6. **MEDIUM — reconnect keeps stale state.** `connect()` (`driver.py:203-266`) never re-inits state and `disconnect()` (`:268-284`) resets only `active_connection`: `homed=True` and a stale `_wco` survive a power-cycle reconnect, producing coherent-looking but wrong deck coordinates when `seed_wco()` fails (it only warns, `:640`). Fix: reset transient state (`homed`, `_wco`, `config`) at the top of `connect()` and in `disconnect()`.
7. **MEDIUM — skipped WPos enforcement still accepts motion.** `driver.py:257-263`: when the initial `?` gets no response, connect logs a warning and skips `enforce_wpos_mode()` (G90 + `$10=0`) but proceeds — a controller left in G91 executes the next absolute move as relative. Fix: retry the probe; if still silent, raise `MillConnectionError` instead of continuing un-enforced.
8. **MEDIUM — `home()`'s alarm-retry branch aborts instead of retrying.** `driver.py:519-521` resends `$H` via `execute_command`, which raises `StatusReturnError` on the buffered `ALARM:x` text (`:376-393`). Fix: drain the buffer and wrap the retry so it actually retries.
9. **MEDIUM — missing connection guards.** `current_status`/`clear_buffers`/`seed_wco`/`current_coordinates` (`driver.py:554,588,628,681`) deref `self.ser_mill` unguarded → `AttributeError` instead of `MillConnectionError`. Fix: add the guard `read_config` already uses (`:300-302`).
10. **MEDIUM — session double-connect leaks the old gantry.** `GantrySession.connect()` (`session.py:140-168`) silently replaces `self._gantry` without disconnecting the previous one (open tty handle, background `_move_worker` can still command the old object). Fix: disconnect the old gantry first (or refuse with a clear error — pick one and test it).
11. **LOW —** `unlock()` (`driver.py:461-471`) sleep+drain misses late `$X` errors → readline-until-ok/error with deadline. Strict ascii `decode` (`driver.py:313,321,579`) → `errors="replace"` (a noise byte currently raises `UnicodeDecodeError`, which `gantry.py:230-235` mislabels as coordinate validation). `get_position_info` (`gantry.py:344-351`) returns the same dict for `"coords"` and `"work_pos"` → return copies. `_cache_port` (`driver.py:198-201`) writes `mill_port.txt` into the installed package dir and nothing reads it → delete it (or relocate to `~/.cubos/`). `OfflineGantry.move_to` (`offline.py:33`) lacks the `travel_z` kwarg its callers pass (`instrument_mount.py:75-77`) → add `travel_z=None`. `tests/hardware/test_wpos_enforcement.py:218` calls `mill.stop()` as cleanup (leaves Hold + raises) → `mill.disconnect()`.

## Tests (minimum)

- `stop()`/`feed_hold_realtime()` complete without raising against a mock that reports `Hold`; `resume()` sends `~`.
- Status delivered in two fragments and truncated mid-number → framing either reassembles or discards; never a parsed wrong coordinate.
- `<Alarm|...>` mid-move classified immediately; `is_healthy()` false on `ALARM:1` push; unstripped `ok\r\n` handled.
- Reconnect after disconnect resets `homed`/`_wco`; double `session.connect()` doesn't leak; calibration-finalize failure preserves/effects the soft-limit restore.
- `home()` alarm-retry actually retries; unguarded methods now raise `MillConnectionError` before connect.
