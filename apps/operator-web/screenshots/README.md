# Run view screenshots

Generated by the E2E suite, not hand-captured:

```bash
cd apps/operator-web && npx playwright test tests/e2e/run-steps.spec.ts
```

Each image is the whole operator workspace in the Run view, rendered by the
real app against the hermetic API mock in `tests/e2e/apiMocks.ts` (no backend,
no hardware). The scenarios live in `tests/e2e/run-steps.spec.ts`, which pins
`Date.now`/`Math.random` so regenerating produces byte-identical files rather
than a spurious binary diff.

| File | Scenario |
| ---- | -------- |
| `run-view-liquid-handling.png` | A run mid-transfer, with compound-command substeps nested under their step. |
| `run-view-resumed.png` | A resumed run: steps the fluid journal reports as already applied are marked skipped, with the reason spelled out. |
| `run-view-failed.png` | A failed run: the failing step is named with its error; steps that were never reached stay pending. |

Regenerate them whenever the run view's layout or status vocabulary changes.
